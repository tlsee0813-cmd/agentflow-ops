# 같은 노트북에서 계정을 바꿀 때 유지하는 환경

Codex 총괄 로그인만 교체한다. 아래 공통 환경은 계정마다 다시 설치하지 않는다.

| 구분 | 공통으로 유지하는 것 | 확인한 범위 |
|---|---|---|
| 총괄 스킬 | 개인 `agentflow-coordinator`와 로컬 runtime 경로 | 실제 전환 후 파일 유지 |
| 저장소 작업 | 동일 checkout, Git Credential Manager의 Windows 사용자 인증 | 사용자 GitHub 로그인 완료 후 비대화형 `git push --dry-run origin HEAD:main` 성공 |
| 웹 Pro | Oracle 전용 브라우저 프로필과 sessionId | 실제 전환 후 기존 완료 기록 조회 성공 |
| Claude Code 웹 | 기존 로그인과 작업 URL | 실제 전환 후 같은 작업 답변 회수 성공 |
| DSH | 설치된 런타임과 비공개 키 파일 | 실제 전환 후 doctor 성공; 키 내용 출력 안 함 |
| 계정 전환기 | 원본 vault와 역할 매핑 | 실제 Pro → Business 전환 및 같은 대화 재개 성공 |

GitHub connector는 현재 Codex 로그인 계정에서 제공되는 연결이다. 실제 계정 변경 중 connector 도구가 사라진 경우가 있었다. 따라서 파일 fetch·commit·push는 공통 로컬 Git을 기본 경로로 쓴다. 같은 GitHub 사용자 인증을 Codex 프로필별로 복제하지 않는다. GitHub 앱 연결이 없는 계정에서도 로컬 Git으로 저장소 작업을 이어갈 수 있다.

Git만으로 이슈·PR의 API 기능까지 대체했다고 표현하지 않는다. 해당 작업에는 그 계정에서 사용 가능한 GitHub connector나 별도로 준비된 인증된 GitHub CLI가 필요하다. 이 문서는 GitHub CLI 설치·로그인을 완료했다고 주장하지 않는다.

앱의 플러그인/커넥터 권한은 각 계정에서 한 번 승인해야 할 수 있다. 모든 계정을 지금 다시 순회하거나 기존 브라우저 로그인을 바꾸는 대신, 공통 로컬 경로를 우선 사용하고 계정별 도구가 실제 필요한 시점에만 연결 상태를 확인한다. 새 총괄에서는 자기 thread UUID에 자동 감시를 연결하는 설정만 별도로 필요하다.

Git 인증은 Git Credential Manager가 보관한다. 계정 문서에 비밀번호·토큰을 쓰거나 GitHub에 올리지 않는다. 창이 열렸다는 것, 웹 로그인 완료, CLI 자격 저장 완료는 서로 다르므로 마지막은 비대화형 권한 점검으로 확인한다.


자동 감시와 계정 전환은 로컬 프로그램이 수행한다. 감시를 위해 모델에 대화 원문을 반복 전송하지 않는다. 최신 호환 어댑터의 snapshot 크기·읽기 비용은 계정 운영 문서에 기록한다.
