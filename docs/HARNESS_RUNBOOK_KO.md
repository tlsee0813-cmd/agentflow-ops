# AgentFlow 작업 분배 하네스

2026-10-23. 현재 적용 범위는 저장소 AGENTS.md와 작업 지시·결과 규약이다. 별도 상주 조정 서버나 모델 자동 전환기를 설치했다는 뜻은 아니다. 실제 채널 연결 상태는 STATUS.md가 기준이다.

## 선택

현재 Codex 총괄과 기존 Oracle를 유지한다. js-jony-k/codex-harness의 적은 수의 워커, 제한된 재시도, 짧은 결과 반환 원칙과 Superpowers의 작업별 문맥 전달 원칙을 참고해 우리 운영 지침으로 작성했다. upstream 문서·코드를 통째로 복제하거나 모든 작업에 동일한 다단계 리뷰를 붙이지 않는다.

| 일 | 우선 경로 | 총괄에게 돌아올 것 |
|---|---|---|
| 넓은 최신 조사·유사 UI·OSS 대안 | 웹 ChatGPT Pro, 주제별 세션 | 후보 차이·실제 소스·권장안·반례 |
| 경계가 정해진 구현·수정 | 기존 Claude Code | 변경·검증·커밋/PR |
| 독립 실행·재현·화면 확인 | Codex Cloud와 허용된 브라우저 | 기준 SHA·실제 조작·증거·실패 |
| 로컬 확인·짧은 통합·연결 문제 | 6.1 Sol High 보조 담당 | 확인 결과와 필요한 수정 |
| 목적 충돌·복잡한 설계·중요 검토 의견의 판정 | 총괄 또는 Astra High 한 명 | 이유 있는 선택과 통합 기준 |
| 좁은 추출·분류·초안 | 검증 후 DSH/DeepSeek | 구조화 결과와 불확실한 항목 |

내장 워커는 사용자 지정 모델을 따른다. 외부 서비스는 자기 로그인·요금제·사용 한도를 쓰며 무료 또는 무제한이라고 가정하지 않는다. Cloud가 로컬과 같은 Codex 계정을 쓰면 독립된 한도라고 가정하지 않는다. 웹 Pro 조사 계정과 로컬 총괄의 계정 회전 우선순위는 별개다.

## 한 작업의 흐름

1. 총괄이 현재 제품 목표와 완료 조건을 잡는다. 범위가 좁은 변경은 직접 처리해도 된다.
2. 관련 파일과 기준 SHA만 넣은 WORK_ORDER를 보낸다. 서로 독립인 연구·구현·검증을 분리하고 한 파일의 작성자를 지정한다.
3. 접수 ID를 기록한다. Oracle는 기존 sessionId로 wait/harvest하고, Cloud·Claude도 실제 작업 ID·대화 링크로 이어간다. 응답 지연을 실패로 간주해 중복 배정하지 않는다. Oracle 소스에서 wait는 completed 이외의 종료도 반환하며 output은 로그 꼬리다. 상태와 response.md 등 전체 결과를 함께 확인한다. 최신 소스와 설치 버전의 차이는 채널 조사 문서에 기록한다.
4. 기다리는 동안 총괄은 다른 독립 작업을 한다. 같은 화면·세션에 동시 입력하지 않는다. 연결 오류는 보조 담당에게 한정된 진단을 맡기고 다른 채널의 일을 계속한다.
5. WORK_RESULT의 결론과 근거를 읽고 채택·수정·보류를 정한다. 결론에 영향을 주는 코드/원문과 중요한 조작은 직접 또는 독립 담당으로 확인한다.
6. 중요한 변경만 별도 독립 검증을 거친다. 새 근거 없이 검토를 반복하지 않는다. 현재 상태는 STATUS 또는 제품의 ACTIVE 한 곳에 통합한다.

## 문맥과 비용

작업 범위가 같은 후속 질문은 기존 worker 세션에 델타만 보낸다. 주제가 달라지거나 문맥이 오염되면 새 세션에 짧은 인계문을 준다. 총괄의 전체 대화와 모든 문서를 워커마다 복제하지 않는다. 상세 자료는 링크로 보관하고 필요한 경우에만 읽는다.

의미 있는 다음 제품 작업에서 조사·구현·검증별 담당, 재시도, 경과 시간, 결과 통과 여부를 기록한다. 실제 토큰 수가 제공되는 채널만 토큰을 기록한다. 종전과 같은 난도의 작업끼리 비교하며 정답률·검증 품질이 떨어지면 낮은 모델 배정을 되돌린다. 전체 Astra 한도가 몇 % 줄어든다는 보장은 아직 없다.

## 지금 가져오지 않는 부분

- 새로운 범용 대화 bus·큐·항상 켜진 워커 풀: 기존 Oracle/Cloud의 세션 기능부터 검증한다.
- 전체 시스템 프롬프트 교체: 현재 도구·권한·작업 규칙과 충돌할 수 있다.
- 무조건 두 단계 이상의 다중 리뷰: 변경 위험과 새 근거가 있을 때만 늘린다.
- RTK 자동 hook: 터미널 출력 압축과 실제 Astra 한도 절감은 다르다. 현재 PowerShell/exec 호출에 hook이 적용되는지 확인되지 않아 자동 설치하지 않았다. 직접 호출의 이득이 있는 반복 명령부터 별도 비교할 수 있다.
