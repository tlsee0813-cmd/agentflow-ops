# 조립 방향과 선택 근거

2026-10-23 기준. 현재 계정 후보의 우선 비교 순서는 [ACCOUNT_DECISION_KO](ACCOUNT_DECISION_KO.md), 실제 실행 여부는 [STATUS](STATUS.md)에 모읍니다.

## 판단 순서

1. **계정이 깔끔하게 바뀌고 같은 총괄 작업을 이어갈 수 있는가?**
2. **이전에 하던 조사·위임·화면 조작·검증·GitHub 결과 회수를 그대로 또는 더 편하게 할 수 있는가?**
3. 그 두 조건에 도움이 되는 기존 도구만 추가한다.

같은 노트북에서 대화와 브라우저 세션이 유지되는 것은 사용자가 확인한 운영 전제다. 기억 이전·브라우저 복제 기능은 이 조립의 선행 조건이 아니다. Codex 앱을 유지하는 경로와 CLI 경로를 모두 허용하며, 도구 교체 자체를 목표로 하지 않는다.

## 계정 전환을 먼저

**QuotaCrew v0.3.0을 자동화 후보로 두고, codex-switch와 전환 품질을 먼저 비교한다.** 제공된 codex-switch를 조사한 뒤 GitHub를 추가 검색해 발견했다. Windows에서 사용량 확인 → 사용 가능한 계정 선택 → 실제 로그인 적용·검증 → 같은 대화의 재개 요청·관찰을 이미 구현한다. 우리가 외부 watcher나 계정 적용 코드를 새로 만들 필요가 줄어든다.

코드에서 자동 선택 시 오래되거나 불확실한 계정 상태를 제외하고, 검증된 한도 중단을 대상으로 하며, 같은 thread/turn의 재개 claim 중복을 막는 경로를 확인했다. Desktop·IDE 재개는 upstream에서도 실험적이며 버전 의존이다. CLI/App Server 대화도 지원 경로가 있지만 원래 터미널 프로세스를 제자리에서 교체한다는 뜻은 아니다. **이 노트북에서의 실제 계정 교체·재개 성공은 아직 확인하지 않았다.**

중요한 차이가 있다. QuotaCrew는 Windows에서 패키지 Codex 앱을 psutil.terminate()로 종료하며, 설치된 Desktop의 재시작을 끄는 사용자 옵션은 확인하지 못했다. Codex의 자식으로 실행됐으면 전환을 거절하므로 독립 실행이 필요하다. 설정은 다른 항목을 보존하되 인증 저장소를 file로 바꾸고, auth/config 복구 snapshot을 둔다. 자동 재개는 한도 중단 대화들에 적용될 수 있어 지정 총괄 한 개만의 allowlist가 있다고 가정하지 않는다.

기존 codex-switch는 정상 종료를 요청하는 Restart Manager 경로가 있어 전환 부드러움의 비교 기준으로 남긴다. Windows의 기존 --switch-account 명령과 완료 상태 파일이 있다. 다만 기본 구현이 모든 active thread를 잡는 점과 자동 회전 정책이 없는 점은 남는다. QuotaCrew의 넓은 자동화 기능만으로 전환 품질 관문까지 통과했다고 판단하지 않는다. 같은 Codex Home을 관리하는 계정 관리자 두 개를 동시에 운영하지 않는다.

CC Switch의 최신판에도 실제 공식 계정 direct 변경이 있다. 그러나 이번 목적보다 provider·설정 관리 범위가 넓고, 같은 한도 중단 대화의 자동 재개까지 이번 조사에서 확인하지 못했다. CLIProxyAPI는 별도 요청 프록시와 provider 설정을 추가하므로 우선 조합에서 뺀다.

## 이전 작업과 함께 쓰기

~~~mermaid
flowchart LR
  A[QuotaCrew: 계정 확인·교체·재개] --> C[로컬 총괄]
  G[GitHub: 작업 기준·현재 상태] --> C
  C --> P[Oracle: Pro 조사·비판]
  C --> L[기존 Claude 환경: 구현·검토]
  C --> X[기존 Cloud: 독립 실행·검증]
  C --> B[브라우저: 화면 관찰·조작]
  C -. 후순위 .-> D[DSH: 좁은 자료 처리]
  P --> R[GitHub: 결과·접근 가능한 증거]
  L --> R
  X --> R
  B --> R
  D --> R
  R --> J[총괄 판단·통합]
  J --> G
~~~

웹 Pro 경로는 Oracle를 먼저 재사용한다. Windows의 기존 Chrome 연결, 파일·이미지 입력, detached 실행, 저장 세션의 wait/harvest/followup이 이미 있다. MCP를 직접 쓰는 AI는 Oracle MCP를 등록하면 되고, CLI에서 호출하는 AI는 mcporter를 사용한다. 새로운 전송 큐·웹 대시보드·자체 세션 저장소를 만들지 않는다.

현재 설정은 browser engine, 기존 Chrome 연결, manualLogin=false, cookieSync=false, 대화 archive=never다. 실제 MCP dry run에서 이 설정이 적용됨을 확인했다. 모델 UI의 선택 증거와 최종 내부 생성 모델의 인증은 구분한다. 응답이 늦어도 같은 실제 sessionId로 기다리며, restart를 회수 대용으로 호출하지 않는다.

Codex Cloud는 현재 CLI와 기존 브라우저를 사용한다. 목록 JSON은 실제 조회했지만 제출 응답·작업 완료 상태·산출물 회수는 아직 표본이 없다. 이 부분은 원래 Cloud 명령으로 짧은 작업 하나를 확인하면 되며 새 연결기를 먼저 만들 이유가 없다.

Claude는 사용자가 사용하는 기존 Code 환경을 유지한다. 이 로컬 PATH에 실행 파일이 없다는 사실을 기존 Claude 작업 환경이 없다는 뜻으로 해석하지 않는다. 호출 경로가 확인되기 전까지 검증되지 않은 로컬 CLI 명령을 자동 실행 구성에 넣지 않는다.

## 화면 점검을 잃지 않기

Oracle의 이미지 첨부는 자료를 모델에 전달하는 기능이다. Dify 등을 실제 조작해서 비교하거나 화면 비율·계층·탐색 복귀를 확인하는 작업에는 기존 브라우저 도구를 계속 사용한다.

추가 후보인 Chrome DevTools MCP 1.12.0은 기존 Chrome 연결, snapshot, 스크린샷, 클릭·입력·드래그, 좌표 조작을 지원한다. 기존 CUA 경로보다 낫다는 실사용 근거가 생긴 부분만 채택한다. 이번 mcporter 경유 연결 시도는 기존 Chrome 소유권 정책에서 거절돼 재시도하지 않았다. 이 연결을 위해 OpenClaw나 또 다른 브라우저 관리 체계를 먼저 도입하지 않는다.

## AI가 쓰기 편한 운영

한 세션에는 이어지는 주제 하나를 맡긴다. 예를 들어 공간 탐색 조사, 구현, 독립 화면 점검을 분리하고 서로 독립인 작업은 병렬로 진행한다. 같은 대화·같은 탭의 동시 입력은 피한다.

작업 입력에는 목적, 기준 GitHub SHA, 읽을 경로, 필요한 대표 화면, 범위와 완료 조건을 적는다. 전체 저장소를 매번 첨부하기보다 관련 파일과 변경만 보낸다. 결과에는 실제 세션/작업 ID와 링크, 확인한 근거, 제안, 미실행 항목을 남긴다. 총괄은 이를 그대로 전달하는 데서 끝내지 않고 채택·보류·기각과 통합을 맡는다.

GitHub에는 작업 기준·정리된 결과·대표 증거를 둔다. 로컬에는 도구 설치·native 세션·임시 출력처럼 실행에 필요한 것만 둔다. 공개 저장소에 자격증명이나 원본 계정 로그를 자동 업로드하지 않는다.

## 최신성 관리

새 작업을 시작하거나 실제 오류가 생기면 upstream의 최신 release·최근 commit·관련 issue를 확인한다. 설치 버전과 검토한 main SHA를 따로 기록한다. 최신이라는 이유만으로 오류가 적다고 단정하지 않고, 우리에게 필요한 수정이 배포됐는지 확인한 뒤 업데이트한다. 현재 사용 버전은 잠금 파일로 재현한다.

Oracle 최신 main은 현재 npm 배포판보다 로그인 UI 판정 수정과 의존성 갱신 두 커밋 앞선다. 이 수정이 필요한 증상이 실제로 나오면 해당 수정이 담긴 배포판이나 upstream가 제공하는 소스 설치 경로를 사용한다. 불필요한 상시 fork는 만들지 않는다.

## 다음 순서

먼저 계정 도구의 종료 방식·설정 변경·재개 대상을 비교하고, 이 노트북에서 계정 교체·같은 총괄 재개를 확인한다. 그다음 Pro 질문·회수와 기존 Claude·Cloud·화면·GitHub 흐름을 비교표로 대조한다. 반복되는 좁은 작업에 이득이 있을 때 DSH 한 개를 추가한다. 제품 연구와 이 도구 조립은 별도 저장소에서 관리한다.

계정 후보의 현재 우선 비교 순서와 종료·설정 변경 차이는 [ACCOUNT_DECISION_KO](ACCOUNT_DECISION_KO.md)를 따른다. Switchy 1.0.39는 실제 준비 후 접근 제한 차이로 보류·중지했다. QuotaCrew 원본 CLI 준비와 실제 전환의 미실행 상태는 STATUS를 따른다.
