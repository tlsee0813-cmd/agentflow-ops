# 기존 작업과의 비교 기준

계정 전환이 첫 관문이다. 나머지는 기존 작업을 잃지 않고 더 편해지는지 확인한다. 점수를 임의로 합산하지 않고, 각 경로의 실제 관찰을 기록한다.

| 관문·기존 작업 | 조립 후 확인할 동작 | 현재 근거 |
| --- | --- | --- |
| **계정 교체** | 대상 계정이 실제 적용되고 사용 가능 상태를 확인 | 두 Business 사용자+기존 canonical을 G 원본 vault에 보관, 독립 실행과 실제 quota 조회 완료. actual 교체는 미실행 |
| **같은 총괄 이어가기** | 같은 대화의 작업을 한 번 이어가고, 다른 대화에 엉뚱한 재개 입력을 보내지 않음 | G 원본 IPC가 현재 active 총괄 UUID 하나를 감지했고 owner RPC 확인. 실제 교체 뒤 동일 UUID 재개는 미확인 |
| 세션·브라우저 유지 | 기존 작업 링크·브라우저 대화에 다시 접근 | 같은 노트북에서 유지된다는 사용자 확인을 운영 전제로 채택. 이번 준비 후 Codex 로그인 상태·GitHub 읽기 성공 |
| Pro 질문 → 다른 일 → 회수 | 별도 주제에 질문 후 같은 실제 sessionId의 최종 답변 회수 | Oracle 설치·도구 조회·dry run 성공. live 왕복 미실행 |
| 주제별 병렬 작업 | 조사·구현·독립 검증 세션 분리 | 기존 운영 방식 유지. native Oracle 세션을 추가로 활용 |
| Claude 위임·이어가기 | 기존 Code 환경에 배정하고 같은 작업 결과 회수 | 기존 접속 경로 유지. 이 로컬 PATH의 CLI는 미발견 |
| Cloud 검증 | 기준 SHA/브랜치의 작업 제출 → 상태 확인 → 결과·diff 회수 | 현재 CLI 도움말과 실제 빈 목록 조회 확인. 새 작업 미제출 |
| 화면 보기·조작 | Dify/프로젝트 화면의 클릭·입력·캔버스 조작·스크린샷 확인 | 기존 도구 유지 방침. 현재 Work 설정의 로컬 브라우저 비활성화 오류로 live 점검 대기 |
| 이미지 검토 | 모델 첨부와 총괄의 실제 시각 확인을 구분 | Oracle 첨부 설정 dry run 확인. 실제 이미지 왕복 미실행 |
| GitHub 인계·통합 | 다른 세션이 입력·결과·대표 증거를 회수 | 이 저장소 문서·설정과 source pin 사용. native 원본 세션 전체는 비공개 로컬 |
| 총괄 판단 | 다른 AI의 주장을 원문·코드·화면과 대조하고 반영 여부 결정 | 도구가 대신 판정하는 구조를 추가하지 않음 |
| DeepSeek 추가 | 좁은 반복 작업 한 개에서 결과·비용·회수 부담 확인 | DSH helper 소스만 검토. 후순위 |

첫 계정 전환 확인은 현재 총괄이 커밋·배포·전송 중인 순간을 피해서 한다. 전환 전후 현재 계정·같은 대화·실행 중 작업·GitHub 읽기·기존 외부 작업 회수를 확인한다. 기억 이전을 별도 제품으로 시험하지 않는다.

전환 요청 성공과 실제 작업 재개는 구분한다. 프로세스 exit 0, GUI의 전환 표시, 모델 답변 완료 중 하나만으로 전체 관문을 통과했다고 기록하지 않는다. 실패·불확실 전송은 기존 도구의 복구 경로를 사용한다.

이 표의 미확인을 구현 결함으로 확정하지 않는다. 반대로 소스에 기능이 있다는 사실을 이 노트북의 사용 성공으로 확대하지 않는다.
